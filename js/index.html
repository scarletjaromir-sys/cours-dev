🧱 C'est quoi un bloc { } ?

Un bloc c'est tout ce qui se trouve entre une accolade ouvrante { et une accolade fermante }. C'est comme une pièce fermée : ce qui est créé à l'intérieur reste à l'intérieur.

DEHORS if (score > 10) { ← accolade ouvrante = début du bloc
DEDANS let message = "Gagné !"; ↑ cette variable n'existe QUE dans ce bloc
} ← accolade fermante = fin du bloc · message n'existe plus ici
💡
Règle simple : une variable let ou const ne vit que dans le bloc { } où elle est née. En dehors, elle est invisible. On appelle ça la portée (scope en anglais).

Exemple concret

let score = 15; // ← DEHORS : visible partout if (score > 10) { // Début du bloc let bonus = 5; // ← DEDANS : existe seulement ici console.log(score); // ✅ OK (score est dehors) console.log(bonus); // ✅ OK (bonus est dedans) } // Fin du bloc → bonus disparaît console.log(score); // ✅ OK console.log(bonus); // ❌ ERREUR : bonus n'existe plus !

🔠 Valeur, type, chaîne… le vocabulaire de base

Avant de coder, il faut connaître ces mots. On les utilise tout le temps.

Valeur Ce qu'on met dans une variable — le contenu réel
Dans let score = 10, la valeur c'est 10.
Dans let nom = "Noah", la valeur c'est "Noah".
La valeur peut être un nombre, du texte, vrai/faux, une liste…
String Chaîne de caractères — du texte
Une suite de lettres, chiffres, espaces, symboles… toujours entre guillemets.
"Bonjour"  ·  'Hello'  ·  "1100 messages"  ·  "a"
⚠️ "42" est une String (texte), pas un nombre — on ne peut pas faire de calcul avec.
Number Nombre — entier ou décimal
Sans guillemets. On peut faire des calculs avec.
42  ·  3.14  ·  1100  ·  -5
Boolean Booléen — seulement deux valeurs possibles : vrai ou faux
true (vrai)  ou  false (faux). Jamais de guillemets, jamais de nombre.
C'est le résultat de toute comparaison : 1100 > 1000 → true
Array Tableau — une liste ordonnée de valeurs
Entre crochets [ ], séparées par des virgules. Chaque case a un numéro qui commence à 0.
["pomme", "banane", "cerise"] → 3 éléments, indices 0, 1, 2
Object Objet — des données regroupées avec des étiquettes
Entre accolades { }. Chaque donnée a un nom (clé) et une valeur.
{ nom: "Noah", age: 13, actif: true }
💡
Résumé facile : le type dit quelle sorte de donnée c'est (texte ? nombre ? vrai/faux ?). La valeur c'est le contenu réel. JS se comporte différemment selon le type — c'est pourquoi 42 + 1 donne 43 mais "42" + 1 donne "421" (collage de texte).

🔀 Structure if / else if / else

🧱 Les blocs { } dans un if

Chaque if, else if et else a son propre bloc. JS n'entre dans un bloc que si la condition est vraie :

if (note >= 16) {← entre ici SEULEMENT si note ≥ 16
console.log("Très bien !");
} else if (note >= 10) {← entre ici si note ≥ 10 (et < 16)
console.log("Reçu");
} else {← entre ici si aucun des blocs précédents n'a été vrai
console.log("Échoué");
}

📐 Sur quoi je branche l'événement ?

Le choix du récepteur change tout :

unElement.addEventListener(...)
Réagit uniquement quand l'action se passe sur cet élément précis.
Ex : un bouton, une div, un input
document.addEventListener(...)
Réagit quand l'action se passe n'importe où dans la page.
Ex : keydown/keypress — peu importe où on clique
window.addEventListener(...)
Réagit sur des événements globaux de la fenêtre.
Ex : scroll, mousemove, load, resize
💡
Règle simple : si l'événement concerne un élément précis → branche sur l'élément. Si ça peut se passer n'importe où (clavier, scroll, chargement) → branche sur document ou window.

📦 L'objet événement e — ce qu'il contient

Quand tu mets (e) dans ta fonction fléchée, JS te passe automatiquement un objet avec des infos sur ce qui vient de se passer.

window.addEventListener("mousemove", (e) => { console.log(e.pageX); // position X de la souris console.log(e.pageY); // position Y de la souris }); document.addEventListener("keydown", (e) => { console.log(e.key); // touche pressée : "a", "Enter", "ArrowLeft"... }); input.addEventListener("input", (e) => { console.log(e.target.value); // texte tapé dans le champ }); form.addEventListener("submit", (e) => { e.preventDefault(); // bloque le rechargement de la page }); document.body.addEventListener("click", (e) => { console.log(e.target); // l'élément précisément cliqué });
⚠️
Le e n'est disponible que si tu le mets dans les parenthèses : (e) =>. Sans lui, tu n'as pas accès à la position de la souris, la touche pressée, etc.

🧠 La méthode universelle en 4 étapes

Cette méthode sépare strictement ce que l'application sait (les données) de ce que l'utilisateur voit (l'affichage). C'est l'architecture utilisée par tous les développeurs modernes.

📌
Le JS ne regarde jamais l'écran pour savoir ce qui se passe — il regarde ses variables. L'écran n'est qu'un reflet des données.
1. LES SÉLECTIONS
Le matériel
On attrape tous les éléments HTML dont on aura besoin.

outil document.querySelector()
règle Toujours dans des const — ces références ne changent pas.
2. L'ÉTAT
Le cerveau
Les variables qui contiennent la "vérité" de l'application à l'instant T.

outil let — car ces valeurs vont changer
ex let score = 0  ·  let isDarkMode = false  ·  let posX = 0
3. updateDisplay
L'affichage
Une fonction unique dont le seul boulot est de synchroniser le HTML/CSS avec les variables de l'étape 2. Elle ne décide de rien, elle obéit à l'état.

outil const updateDisplay = () => { ... }
règle Se place avant les événements dans le fichier.

⚠️ updateDisplay n'est pas un mot-clé JS — c'est un nom choisi. Tu peux l'appeler render(), afficher(), ce que tu veux.
Et cette étape n'est pas toujours nécessaire : pour une action simple comme body.classList.toggle("dark"), tu peux mettre l'action directement dans l'événement. La fonction séparée devient obligatoire dès que plusieurs événements déclenchent la même mise à jour, ou que la logique d'affichage est complexe.
4. LES ÉVÉNEMENTS
Les déclencheurs
On écoute les actions utilisateur. Règle stricte dans chaque événement :

1 On met à jour les données (étape 2)
2 On appelle updateDisplay()

On ne touche jamais au CSS directement ici.

📏 Les règles d'or

Règle 1 — Texte = guillemets, variable = jamais de guillemets

❌ Piège classique
h3.textContent = "count"; // Affiche le MOT "count" // pas la valeur de la variable !
✅ Correct
h3.textContent = count; // Affiche la VALEUR // stockée dans count

Règle 2 — Modifier la donnée D'ABORD, afficher ensuite

❌ Affiche l'ancienne valeur
updateDisplay(); // ← trop tôt count++; // trop tard
✅ Bon ordre
count++; // 1. donnée updateDisplay(); // 2. affichage

Règle 3 — Tu te répètes ? C'est le signal d'une fonction

❌ Code dupliqué = fragile
plus.addEventListener("click", () => { count++; h3.textContent = count; // répété h3.style.color = "green"; // répété }); moins.addEventListener("click", () => { count--; h3.textContent = count; // répété h3.style.color = "red"; // répété });
✅ Fonction = 1 endroit à modifier
const maj = () => { h3.textContent = count; h3.style.color = count > 0 ? "green" : count < 0 ? "red" : "grey"; }; plus.addEventListener("click", () => { count++; maj(); }); moins.addEventListener("click", () => { count--; maj(); });

Règle 4 — L'ordre dans le fichier

Règle 5 — querySelector utilise la syntaxe CSS

document.querySelector("#monId") // id → # document.querySelector(".maClasse") // classe → . document.querySelector("h3") // balise → nom seul document.querySelector(".card button") // imbriqué → comme en CSS
⚠️
querySelector renvoie le premier élément trouvé. Pour tous les récupérer, utilise querySelectorAll — qui renvoie une liste sur laquelle tu peux faire un forEach.
